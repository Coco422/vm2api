## 实际功能与接口

运行控制面时显式设置 `VM2API_COMPANY_ENABLED=true` 才启用员工 API，默认关闭。不修改环境模板；管理员原入口不变，员工入口为 `/cc#/employee`（旧 `/console#/employee` 同样有效）。员工页面不读取管理员 token、面板 Cookie 或面板 API Base，Key 仅在内存中，每次请求重新验证，退出清空整个独立查询缓存。Key 不进入 URL、持久化浏览器存储或查询缓存索引。

| 方法 | 接口 | 作用 |
| --- | --- | --- |
| GET | `/api/company/me` | 员工名、Key 额度、授权且归属本人的 VM 及官方额度 |
| GET | `/api/company/usage?days=7\|30\|90` | 当前 Key 且请求时属于当前员工的用量；上海自然日 |
| GET | `/api/company/requests?day=YYYY-MM-DD&page=1&page_size=20` | 上海自然日内逐笔请求、分页与安全字段投影 |
| POST | `/api/company/vms/:id/refresh` | 刷新上游额度 |
| POST | `/api/company/vms/:id/reset-query` | 查询上游重置券 |
| POST | `/api/company/vms/:id/reset-redeem` | 使用上游重置券，必须携带 `Idempotency-Key` |

鉴权为 `Authorization: Bearer <员工Key>`（服务端也接受既有 `x-api-key`）。POST 要求 `Content-Type: application/json` 且 body 为 `{}`，不接受额外配置参数。仅 active 用户的 oauth 类 Key 可访问；不接受 master、面板会话、无归属 Key、admin/super 所属 Key、api 类 Key、已停用或过期 Key。额度用尽的 Key 仍能读取统计和操作自己的上游重置券，Key 额度保持不变。

VM 权限为 Key 有效范围与员工归属的交集，失效账号池不回落全局池；管理员在 POST 读 body 期间撤销 Key 或重新分配 VM 也会阻断操作。没有匹配的 VM 返回相同 404，不透露他人资源是否存在。只返回显式允许的字段，凭证、代理、组织身份和原始上游错误不回传。

Claude 复用原重置模块的持久化幂等、账号/组织锁与不确定结果保护。OpenAI 另在既有 `settings` 中使用 `company.openai_reset.<vmId>` 保存哈希操作标识、收据和 pending 保护，不新增表或迁移。OpenAI 重置结果未知时禁止员工再次消费，需管理员核对上游后处理该命名设置；不能仅凭客户端超时清除 pending。此机制不替代原管理台的管理权限。

## 管理员分配流程

管理员沿用原管理台的「用户」「虚拟机」「密钥」页面：

1. 创建一个 role=`user`、自建 VM 配额为 0 的员工归属记录。为该记录生成随机管理台密码并由管理员保管；只把员工 Key 交给员工。原 `user` 管理台角色仍具备更多权限，因此不能把管理台密码同时交付。
2. 将采购的订阅导入公司 VM，并把 VM 分配给该员工；一位员工一台 VM 对应一个订阅账号。
3. 创建 `category=oauth`、`user_id=员工` 的 Key。Claude 选择 `group_type=anthropic`，Codex 选择 `openai`，`allowed_vms` 仅选该员工的 VM。不要用默认 `all` 来表达单 VM 绑定。
4. 管理员设置 Key 并发/RPM、请求和金额额度及有效期，在 VM 策略中设置模型范围及槽位并发。员工入口不提供这些写操作。
5. 员工使用同一个 Key 调用推理接口和登录员工工作台。离职或 Key 外泄时停用/轮换 Key；停用员工会使该员工的所有 Key 立即无法鉴权。VM 转交前同时复核 Key 归属与绑定范围。

## 上游维护与未来发布

OpenAI 不确定重置的管理员处理工具为 `scripts/company-reset-review.mjs`：必须显式指定已存在的数据库和 VM，默认只读、不访问网络、不执行迁移。管理员独立核实上游券是否已消费后，才可带 `--confirm-upstream-reviewed --at <刚读取的at>` 将 pending 标为已审阅；旧操作继续返回已处理，避免再次消费。此工具没有生产默认路径，本阶段仅在内存/本地合成测试库验证。

