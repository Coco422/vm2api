# 计费明细与请求体保留

计费来源仍为原生 `usage_logs`，不改变计价规则、接口、表结构或页面布局。

- 关联 VM、账号或 Key 的调用摘要，以及任何带 token、搜索、图像用量或费用的记录长期保留。摘要不包含请求体或响应体；普通日志过期、调试体积限制不会删除这些计费依据，累计金额不会因清理减少。
- 普通无归属、无用量的访问日志默认保留 30 天。生产配置也应为 `logging.retain_days: 30`；管理员可单独调整普通访问日志的期限，计费摘要不受该值影响。
- `request_log_debug` 中的请求与响应体默认保留 3 天，仍可按 `debug_retain_days` 和 `max_mb` 清理。删除请求体后，时间、账号、VM、请求时归属、模型、token 和费用仍可核对。
- 同一台 VM 更换账号后，沿用请求当时的账号 ID 分组。旧账号的费用保留，新账号单独累计；近 30 天统计按请求时间筛选。代理更换不改写历史费用。
- 这次修复不会自动找回此前已清理的数据。历史补账必须从备份逐笔核对并去重，不能把记忆中的金额直接写成余额或倒灌旧库。

回归验证：`node scripts/company-local.mjs test billing-retention request-log usage-logs-repo tenant-billing`。测试包含超过 30 天的旧账号、同 VM 换号、租户隔离、重建仓库实例、重复清理，以及请求体按时间/体积删除后账单保持一致。
